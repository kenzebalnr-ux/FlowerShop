# 3-зертханалық жұмыс — FastAPI REST API

## Мақсат және іске асыру

FastAPI HTTP сұрауларын қабылдайды, кіріс схемаларын тексереді және SQLModel сессиясын тәуелділік ретінде алады. Каталог үшін тізім алу, ID бойынша оқу және тауар қосу маршруттары жасалған. Жазу әрекеті әкімші рөлін талап етеді.

| Сценарий | Күтілетін нәтиже |
|---|---|
| Каталогты оқу | 200 және JSON тізімі |
| Бар тауарды ID арқылы оқу | 200 және объект |
| Жоқ ID | 404 |
| Әкімшінің жарамды тауар қосуы | 201 және сервер берген ID |
| Бос атау немесе теріс баға | 400 |
| Токенсіз қорғалған әрекет | 401 |
| Сатып алушының әкімші әрекеті | 403 |

1–7 әдістемесінде FastAPI-дің әдепкі 422 жауабы көрсетілген. 8-зертхананың 400 қате формат талабына сәйкес жобада RequestValidationError өңдеушісі бірыңғай 400 қайтарады. Валидация сақталған, тек HTTP келісімі кеңейтілген талапқа бейімделді.

`/docs` мекенжайындағы Swagger API схемасынан автоматты түрде құрылады. Құпиясөз хеші API жауабына кірмеуі тиіс. Жеке create/update/read схемалары жүйелік өрістерді клиенттің өзгертуінен қорғайды.

## Қорғау сұрақтарына жауап

1. **REST және GET/POST?** REST ресурстармен HTTP арқылы жұмыс істеу тәсілі. GET оқиды; POST жаңа ресурс жасайды немесе әрекетті орындайды.
2. **Pydantic қызметі?** Типтер мен шектеулерді тексеріп, жарамсыз кірісті бизнес логикаға жібермейді.
3. **Depends не үшін керек?** Әр сұрауға дұрыс ресурс өмірлік циклін береді. Бір жаһандық Session параллель сұраулар үшін қауіпсіз емес.
4. **Swagger қалай жасалады?** FastAPI маршруттар мен схемалардан OpenAPI сипаттамасын құрып, дайын Swagger интерфейсіне береді.
5. **422 нені білдіреді?** JSON синтаксистік тұрғыдан оқылды, бірақ сұрау схема талаптарына сәйкес келмейді.
