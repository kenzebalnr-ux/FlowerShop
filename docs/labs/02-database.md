# 2-зертханалық жұмыс — Дерекқор және SQLModel

## Мақсат

FlowerShop бизнес мәндерін SQLModel кластарына ауыстыру, алғашқы кілттерді, сыртқы кілттерді және объектілік байланыстарды анықтау.

## Деректер байланысы

Категорияда бірнеше тауар болады. Пайдаланушы бірнеше тапсырыс бере алады. Әр тапсырыста бірнеше тапсырыс жолы бар; әр жол белгілі бір тауарды көрсетеді. Тапсырыс жолында тапсырыс кезіндегі баға сақталады, сондықтан каталогтағы кейінгі баға өзгерісі бұрынғы тапсырыс сомасын өзгертпейді.

Дерекқор сессиясы сұрау шегінде ашылып, соңында жабылады. Бастапқы деректер генераторы категориялар мен гүл шоқтарын енгізеді. Қайта іске қосу қайталанған каталог жасамауы тиіс. Жасанды деректер нақты сатып алушылардың деректері болып саналмайды.

## Тексеру

1. Backend іске қосылғанда кестелер құрылады.
2. Категориялар мен тауарлар API арқылы көрінеді.
3. Жарамсыз сыртқы кілтке операция қабылданбайды.
4. Бір транзакция сәтсіз болса, оның өзгерістері rollback арқылы кері қайтарылады.
5. `.db` файлы Git тарихына кірмейді; қайта жасауға арналған код сақталады.

Нақты автоматтандырылған тексеру нәтижелері [8-зертхана есебінде](08-testing-report.md) беріледі.

## Қорғау сұрақтарына жауап

1. **ORM дегеніміз не?** Python объектілері мен реляциялық кестелер арасындағы сәйкестік қабаты. Ол параметрленген сұраулар құруды жеңілдетеді.
2. **foreign_key пен Relationship айырмасы?** Біріншісі кестелер арасындағы сілтемелік бүтіндікті сипаттайды; екіншісі Python ішінде байланысты объектілерге қол жеткізеді.
3. **Seed не үшін керек?** Бос жүйені бірден қарап, іздеу және бизнес операцияларын сынауға мүмкіндік береді.
4. **echo=True не береді?** SQL сұрауларын журналға шығарады. Өндірісте артық немесе сезімтал ақпаратты жарияламау үшін өшіріледі.
5. **Неге БД файлы Git-ке салынбайды?** Ол өзгермелі орындалу дерегі және пайдаланушы ақпаратын қамтуы мүмкін. Репозиторийге модель мен seed жеткілікті.
