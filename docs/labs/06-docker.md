# 6-зертханалық жұмыс — Docker және Docker Compose

## Мақсат

Backend пен Streamlit интерфейсін бір командамен іске қосып, сервистердің байланысын және SQLite деректерінің сақталуын қамтамасыз ету.

## Құрылым

`backend/Dockerfile` FastAPI мен витринаны іске қосады. `frontend/Dockerfile` Streamlit интерфейсін іске қосады. Compose ішіндегі `frontend` сервисі API-ге `http://backend:8000` арқылы қатынайды. Браузер хосттың `localhost:8000` және `localhost:8501` порттарын қолданады.

SQLite деректері Docker named volume ішінде сақталады. Қалыпты `docker compose down` volume-ді жоймайды. `docker compose down -v` деректерді жояды, сондықтан оны тек деректерді әдейі тазарту қажет болғанда қолдану керек.

## Командалар

```bash
docker compose up --build
# Бөлек терминалда
docker compose ps
docker compose logs backend
docker compose down
```

GitHub Actions ішінде Compose конфигурациясы тексеріліп, backend және frontend образдары сәтті құрастырылды: [нақты CI нәтижесі](https://github.com/kenzebalnr-ux/FlowerShop/actions/runs/45587968844). Браузер сценарийлері жергілікті Uvicorn және Streamlit серверлерінде тексерілді. Docker build нәтижесі толық контейнерлік end-to-end тест деп көрсетілмейді.

## Қорғау сұрақтарына жауап

1. **Контейнер мен VM?** Контейнер хост ядросын бөліседі; VM жеке қонақ операциялық жүйесін іске қосады.
2. **Dockerfile нұсқаулары?** WORKDIR жұмыс бумасын, COPY файл көшіруді, RUN build кезіндегі команданы, CMD контейнер стартын, EXPOSE қолданылатын портты сипаттайды. EXPOSE портты хостқа өздігінен шығармайды.
3. **.dockerignore?** Артық және құпия файлдарды build контекстінен алып тастайды. Жергілікті venv басқа ортаға сәйкес келмеуі мүмкін және образды үлкейтеді.
4. **backend атауы қалай табылады?** Compose желісіндегі Docker DNS сервис атауын контейнер мекенжайына шешеді.
5. **Деректі қалай сақтаймыз?** БД файлын контейнердің уақытша қабатында қалдырмай, volume-ге орналастырамыз.
